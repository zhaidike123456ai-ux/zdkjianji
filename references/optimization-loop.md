# Skill 优化循环

每个项目结束后执行：

1. 收集实际问题：预览卡顿、识别错误、时间轴错位、转场冲突、编码兼容性和用户返工点。
2. 判断是否可复现：至少有明确时间码、日志、截图或媒体探测结果。
3. 判断是否通用：只更新跨素材仍成立的规则；项目专属文案不写入 Skill。
4. 选择修改位置：流程写入 `SKILL.md`，细则写入 `references/`，重复机械操作写入 `scripts/`，稳定视觉骨架写入 `assets/`。
5. 运行 `quick_validate.py`、脚本测试和一个代表性前向测试。
6. 检查 Skill 是否仍简洁，删除重复和过时说明。

优先吸收能减少返工或避免交付事故的经验。不要仅因为某个审美偏好出现一次，就把它固化为默认规则。
